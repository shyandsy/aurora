# design-nav:一个项目一个『设计导航』(全项目统一模式)

> ⛔⛔ **绝不发布 claude.ai artifact。** 本 skill 的唯一产出是**写进项目 git 仓库的文件**(壳 `index.html` + 子页 `d/*.html`),查看用本地 `http.server`。
> **不要调用 Artifact 工具、不要 publish、不要生成任何 artifact 链接** —— 哪怕平台默认/`artifact-design` 倾向把 HTML 发成 artifact,**这里一律不发**。
> 做完交给用户的是**仓库路径 + 一行 `http.server` 命令**,不是 artifact 链接。
> **唯一例外**:用户**明确开口**要(如"发个 artifact / 给我个在线链接");否则**一次都不发**。

> 目标:**任何项目拿到本 skill,都能产出组织结构统一、规范先行、内容清晰的合格设计文档。**
> doctrine(同 `user-module-migration` 的"表归 aurora、数据归项目"):**壳模板 + 组织规则归本 skill;各项目的实例数据(navigator URL、sidebar 文件路径、子页清单)归各项目自己记录。**

每个项目在**自己的 git 仓库**里维护一组 standalone HTML 作『设计导航』(如 `doc/design/nav/`:壳 `index.html` + 子页 `d/*.html`)——**源头在仓库、版本化、能自托管、不绑 claude 账号**(账号/订阅没了也在)。形态:全宽双栏,左栏深色品牌轨=按**端/页**的列表,右栏 iframe 全宽放当前页设计稿;点左栏切页、`#<k>` hash 深链、每页标「有稿/待补」+ 顶部覆盖率。

## 运行环境(钉死)

设计导航就是**仓库里的一组静态 HTML**,运行/查看方式固定,别发明别的:

- **本地看(默认,单人自用就到此)**:在 nav 目录起一个本地静态服务 ——
  `python3 -m http.server -d <nav目录> 0`(**端口 0 = 系统自动挑一个空闲口**,启动时打印实际端口,如 `Serving HTTP on … port 58115`)→ 浏览器开打印出的 `http://localhost:<该端口>`。
  **别写死端口**:多个项目/多次同时跑各自拿到不同空闲口、不撞;非要固定就填个数字(如 8000),但撞了要自己换。
- **必须走 http(localhost),别 `file://` 双击 `index.html`**:切页/定位靠壳**同源读 iframe**;`file://` 下浏览器把每个文件当独立源会拦(子页能显示但切换/定位失灵),`http://localhost` 下同源才正常。单张设计稿 `d/<x>.html` 自包含,双击能单看。
- **默认一次都不发 claude.ai artifact**(见顶部 ⛔):本地自用根本不需要。源头永远是 git 仓库、查看永远用本地 `http.server`。**只有用户明确开口要在线链接**时,才可发一个 artifact 当预览——此外绝不碰 Artifact 工具。
- 要一个长期稳定 URL(多设备/团队):把 nav 目录挂到现有 web 容器的一个静态 location,或 GitHub Pages —— 仍是**静态托管,不建服务**(设计图是纯静态,不需要后端/artifact 服务)。

## 适用范围与边界(先看这个,别用错场景)

design-nav 是**设计的收口 + 保真 + 规范先行纪律**,**不是审美引擎**:它不替你造设计系统(配色/字阶/组件语言)、不做信息架构(IA)。按场景:

- **主场 · 给已实现的 app 补/同步设计**:真实组件可对,`1:1 还原` 正好发力。→ 新增页=场景 3、改局部=场景 4、同步过时=场景 5。
- **存量 mockup 收口**:能把现有图丢进壳(iframe 一放就渲染),但**达到"合格"是逐页返工,不是"收集一下"**(旧图各画各、无共享 token、脱离/先于真实组件、没定位钩子)。别低估。→ 执行流程见 **§按场景 · 场景 2**。
- **全新项目(greenfield)**:组件还不存在 → `1:1 还原` 是反的、没有 sidebar 可镜像。design-nav 只给**组织纪律 + 运行环境**;**设计系统靠 `artifact-design`、页面清单(IA)靠产品** —— 三者合用才够。→ 执行流程见 **§按场景 · 场景 1**。
- **white-label / 多渠道项目**:`PROJECT` 与 `<title>` 用**中性产品名**,渠道品牌名**别固化进共享壳或子页**(违反中性/白标铁律)。

## 六条铁律(钉死,不许改)

> ⚠️ **greenfield 例外**:代码还没有时,③「镜像真实 sidebar」与画稿铁律①「读真实源码 1:1 还原」**暂不适用**(端/页来自产品 IA、设计先于实现);代码落地后再对齐。详见 §适用范围。其余铁律(规范先行 / 用壳 / 顶层只放端 / 列全标覆盖率 / 一个导航 / 全宽)**一律适用**。

1. **规范先行。** navigator 的**第一个顶层端必须是「规范 · Design Tokens」**,定义本项目的 **色 / 字号 / 间距 / 圆角边框 / 组件样例** —— 整套设计的唯一真源。**先有规范页,再画任何业务页;所有页面设计稿一律照规范,绝不自己发明字号字色。** 项目若已有设计系统文件(如 `web/<app>/DESIGN.md`、`<app>/static/style.css` 之类),规范页就是它的可视化还原。没有就先建规范页。

2. **用本 skill 的壳,别从头写。** 复制 `template/index.html` 当壳(全项目同一个:同样的两栏布局、深色轨、覆盖率、iframe 子页、nav 机制、主题适配)。**只改 `ENDS` 数据数组 + 顶部两处项目名(`<title>` 与 `PROJECT` 常量)**,别动 CSS/JS/布局。这是"组织结构统一"的保证。

3. **镜像真实 app 结构,顶层是"端"。** 左栏分组/页名/顺序**照抄该项目真实的侧边栏/路由**,别凭设计稿文件名瞎编。**顶层只放"端"**(如 规范 / 移动端 / web 控制台 / 其它独立子前端);每个端内部的**可展开子菜单**做成**缩进子组**,**绝不**提成顶层端。web 端结构读该项目前端的 sidebar 菜单定义(Angular 通常 `.../shared/components/sidebar/sidebar.component.ts` 的 `buildMenu()`)+ `app.routes.ts`。

4. **列全 + 标覆盖率。** 真实结构里**每一页都列**,无论有没有稿:有稿=绿点、无稿=灰点+`待补`标签;顶部显示 `X/N 页有稿`。点"待补"页右侧出占位,不装样子。目的=一眼看到覆盖到哪、还差哪。

5. **一个导航,绝不碎片化。** 一个项目所有设计稿都是**同一个** navigator 的子页。**绝不**给单个页面/功能单独开 claude artifact(碎、没法切;claude.ai 顶部那个下拉是"管理/All artifacts 列表",不是页面切换器)。新稿**改仓库那一个导航**(`d/` 加子页 + 填 `ENDS`),不另开图、不另发 artifact。

6. **全宽,不要居中窄框**(`max-width;margin:0 auto` 禁用),左栏才有空间放页面列表。

## 规范页必含什么(铁律1 展开)

「规范 · Design Tokens」页是整套设计的唯一真源,必须把下面五类**可视化**(每项带实样 + 可照抄的 class/值),业务页一律从这里取,不自造:

1. **字号档位** —— 限定几档(如 2xl/lg/base/sm/xs 五档)、标明最小字号与正文字号,禁用档外任意值。
2. **字色** —— 标题 / 正文 / 值(等宽强调)/ 标签 label / 弱化元信息 / 链接 / 分组 eyebrow,各给 token。
3. **语义色** —— 成功 / 警告 / 危险 / 主操作 / 强调 / 中性,**与主色分开**,同一处别堆两个同色芯片。
4. **边框 · 圆角 · 间距** —— 卡片边 / 控件边 / 虚线分隔 / 圆角档 / 内边距 / 区块间距。
5. **组件样例** —— 按钮(主/次/危险/胶囊)、徽章与状态芯片、卡片+spec 行(标签+值)、表单输入,每个附**可照抄的 class**。

项目已有设计系统文件(`web/<app>/DESIGN.md`、`<svc>/static/style.css` 等)时,规范页=把它**可视化还原**;没有就先在这页定下来。

## 画稿铁律(每一页设计稿都要,钉死)

1. **先读真实源码,1:1 还原。** 画某页/某 tab 前,**从头到尾读它真实的页面/组件源码**(`*.component.html` 等,`@if`/条件块起止找准),照着还原真实布局 + 真实 i18n 文案 + 真实 class。**绝不凭空发明布局 / banner / 卡片**(凭空画被骂过)。
2. **只用规范 tokens**,不自造字号字色边框。
3. **设计 == 实现。** 真实有什么画什么;**新增 / 待补用 badge 明确标注**(如 `已有`/`新增`/`待补`),别混进"忠实还原"区误导。
4. **真实内容,不用 lorem。** 用真实 i18n 文案、像样的示例数据(真实格式的 IP/域名/时间);示例数据标明是示例,别冒充真实。
5. **一页画全其关键状态/变体/弹窗**(列表 + 详情 + 空态 + 错误 + 抽屉/弹窗),相邻摆放 → 对应"同页分块放一起"。
6. **载体**:移动端用手机边框画屏;web 页用全宽画布。两者混在同一个导航壳里靠 iframe 各自渲染。

## 子页机制(iframe 隔离)

每份设计稿是**独立自包含 HTML 文件**(自带 CSS、能单独打开、渲染不崩),放 `d/` 下当 iframe 子页 —— iframe 隔离各稿 CSS 类名互撞;**静态服务(http.server / 同目录托管)下子页与壳同源** → 壳可同源控制 iframe 定位(切页/滚动)。壳里每页在 `ENDS` 声明定位:
- `tab:"<id>"` —— 该页在**tab 式**设计文件里(文件内有全局函数按 id 显隐内部 tab,如 `pick(id)` 切 `#tab-<id>`):`frame.contentWindow.pick(id)`。
- `screen:"<关键词>"` —— **画廊式**(一堆屏卡片带页名,如 `.screen`/`.nav`):滚到第一个页名含关键词的屏;同页列表+详情相邻 → 自然"放一起"。
- 都没有 —— 整份就是一页,载入即可。
- `src:null` —— 该真实页**暂无设计稿**,点了出"待补"。

> ⚠️ 不许把多页 splice 进**一个** HTML 用 `pick()/hidden` 切(会 tab 渲染空白,被骂过)。隔离只能靠 **iframe 子页 = 各自独立文件**。

**关于定位的几点(写明,别踩):**
- `tab:` 是**过渡**:只给**遗留的 tab 式设计文件**(一份 HTML 内部多 tab + 全局 `pick()`)留的后门,范围锁在单个子页文件内。**新页别这么画** —— 一页一独立文件(`screen` 或整份单页),不要再在子页里堆内部 tab。
- 定位是 **best-effort,同源前提**:本地 `http.server` / 同目录静态托管下,子页与壳**同源**,`pick()`/`contentDocument` 能过;跨源时(`file://` 双击、或发布成 artifact 被沙箱)`position()` 已包 try/catch —— 只是不自动切 tab/滚动,**iframe 照常显示**,不崩。
- `screen:` 依赖画廊子页用 `.screen` + 页名 `.nav` 的约定;关键词打错 → 静默退回第一屏(可接受,但别打错)。

## 按场景的执行流程(照场景选,别一套步骤套到底)

> 选哪条:没代码的新项目→**1**;已有项目但设计散/没导航→**2**;导航已建、补一整页→**3**;改某页里一块→**4**;代码改了设计过时→**5**;app 菜单结构变了→**6**;把别处/claude 的稿搬进来→**7**。
> 通用约束(所有场景):子页/壳都是**完整 standalone HTML**(带 `<!doctype>`/`<head>`/charset/viewport,模板已带);改完**本地 `http.server` 核对 + 开分支提交进仓库**(见 §运行环境、别碰主 checkout WIP)。

**场景 1 · 全新项目从零(greenfield,还没代码)** —— 设计先于实现,没 sidebar 可镜像。配 `artifact-design` + 产品 IA。
1. 向产品/用户拿**页面清单(IA)**;复制壳进仓库,填 `ENDS`(端/页来自**规划**,全部 `src:null`)。
2. 用 `artifact-design` 定 **token 体系** → 画**规范页**(新定,非还原)。
3. 逐页 **design-first**:按需求发明布局(不读源码),守 token/真实文案/画全状态 → 存 `d/`、flip `src`。
4. 代码落地后 → 转**场景 5**(1:1 同步)+**场景 6**(ENDS 对齐真实 sidebar)。

**场景 2 · 已有项目,按规范重整设计(retrofit)** —— app 有代码、设计散。合格化是逐页返工,别低估,分阶段:
1. **全仓 + claude 清点**现有设计稿(别只扫 doc/design)。
2. 复制壳;**照真实 sidebar/routes 列全** `ENDS`(含待补、缩进子组)。
3. 现有稿逐张搬进 `d/`(headless 的**补全 head**)+ flip `src` → 先得到一个**标覆盖率的导航**(先能看)。
4. **合格化**:建/反推**规范页** → 逐张**重皮到 token** → 对**当前真实组件 1:1 核对**,过时的照场景 5 重画。

**场景 3 · 给项目新增一页设计(导航已建)**
1. 找 `ENDS` 里对应的**真实页**(应已是 `src:null`;没有就按真实 sidebar 补进正确分组/子组,见场景 6)。
2. 读该页真实 `*.component.html` → **1:1 还原**成独立 standalone HTML(用规范 token、画全状态)。
3. 存 `d/<name>.html` → 该页 `src` 从 `null` 改成文件。

**场景 4 · 给某页新增 / 优化局部设计** —— 子页就是个普通 HTML 文件,**直接改 `d/<page>.html` 里那一段**,别为一个局部另开文件/另开图。
- 优化:改那段 markup(仍只用规范 token)。
- 新增局部(新卡片/弹窗/变体):加进去用 **badge 标「新增」**,把该局部的**状态/变体画全、相邻摆放**。

**场景 5 · 设计与实现漂移,同步(维护常态)** —— 代码改了、设计过时。
1. **重读**该页真实 `*.component.html`(找出变化)。
2. 改 `d/<page>.html`:删已移除的、补新增的(badge 标)、对齐布局/文案。1:1 核对。

**场景 6 · app 菜单/路由结构变了,同步导航结构**
1. 重读 `sidebar.component.ts`(`buildMenu()`)+ `app.routes.ts`。
2. 对齐 `ENDS`:新页加进(`src:null` 待补)、改名、调顺序/分组、删已删的页。顶层仍只放端、子菜单仍做缩进子组。

**场景 7 · 把只在别处(claude artifact / 他人)的稿搬进仓库**
1. 导出/读出该稿 HTML;**headless 的补全 head**。
2. 存 `d/<name>.html` → flip 对应页 `src`(没有对应页先按场景 3/6 补)。

> **大小**:仓库里就是普通 HTML 文件,**无上限**。待补页 `src:null` 不占文件。仅当你**另外发布成 artifact 预览**才受 artifact 上限(单文件 16MB、单版本 64MB、≤255 文件),那时有稿页别塞超大内联图(用外链/精简)。

## 合格验收(每个项目自检,全绿才算合格)

- [ ] **规范页排第一**,且含 色/字号/间距/圆角边框/组件 五类(唯一真源);业务页字号字色全取自它。
- [ ] 顶层**只有端**;子菜单做成缩进子组(没有"把子菜单提成顶级端")。
- [ ] 端/页**照真实 sidebar/routes**,顺序一致,一页不漏(含待补页)。
- [ ] 每页标 **有稿/待补** + 顶部 `X/N 覆盖率`。
- [ ] **全宽双栏**;一个链接;左栏可切页、hash 深链。
- [ ] 每份设计稿是**独立可单开 HTML**(iframe 子页),不是 splice 多tab。
- [ ] 业务页设计 = 真实实现 1:1(读过 `*.component.html`),新增/待补用 badge 标清。
- [ ] 内容用真实 i18n 文案 + 像样示例数据(非 lorem);示例数据标明是示例。
- [ ] 一页把关键状态/变体/弹窗画全(列表+详情+空态+错误+抽屉),相邻摆放。
- [ ] 字号字色边框全取自规范页 token,无自造。
